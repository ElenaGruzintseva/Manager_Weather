### Сервис получения и хранения данных о погоде

#### Описание

Проект представляет собой Django-приложение, предназначенное для получения актуальных данных о погоде из внешнего API (Yandex Weather), их хранения в базе данных и предоставления через REST API. Также реализована возможность отправки уведомлений о погоде в Telegram.

Проект построен вокруг пайплайна, который представляет собой последовательное выполнение заранее определенных действий (Actions). 
Каждое действие отвечает за конкретный этап процесса:

 - **FetchWeatherAction**: Получает сырые данные о погоде из внешнего API через WeatherAPIAdapter.
 - **StoreWeatherDataAction**: Сохраняет полученные данные в базу данных WeatherData.
 - **LogWeatherFetchAction**: Отправляет задачу в очередь Celery для асинхронного логирования попытки получения данных в WeatherFetchLog.
 - **NotifyTelegramAction**: Отправляет задачу в очередь Celery для асинхронной отправки уведомления в Telegram (если включено).

#### Преимущества пайплайна:
Легко включать и выключать отдельные этапы, добавлять новые действия.
В разделе settings.PIPELINE_CONFIG можно указать, включено ли конкретное действие.
Если для действия enabled установлено False, оно будет пропущено при выполнении пайплайна.
```
PIPELINE_CONFIG = {
    'fetch_weather': {
        'enabled': True,  # <- Включено
        'timeout': 30,
    },
    'store_data': {
        'enabled': True,  # <- Включено
    },
    'log_to_db': {
        'enabled': True,  # <- Включено
    },
    'notify_telegram': {
        'enabled': False, # <- Отключено
        'bot_token': os.getenv('TELEGRAM_BOT_TOKEN', ''),
        'chat_ids': os.getenv('TELEGRAM_CHAT_IDS', '').split(','),
    }
}
```

#### WeatherAPIAdapter

WeatherAPIAdapter - это ключевой компонент, отвечающий за взаимодействие с внешним API погоды.
Как работает:

FetchWeatherAction использует WeatherDataService, который, в свою очередь, использует WeatherAPIAdapter.
WeatherAPIAdapter использует WeatherAPIClient для выполнения HTTP-запроса к внешнему API.
Ответ от API парсится внутри WeatherAPIAdapter.

Результат парсинга преобразуется в внутреннюю стандартную структуру данных, независимую от конкретного формата ответа API.
Если структура ответа изменилась или парсинг не удался, адаптер не падает, а возвращает None и логирует ошибку, или возвращается стандартная структура данных или последние данные из кэша.

Возможности:

 - Основной пайплайн работает с стандартизированными данными, не завися от деталей внешнего API. При изменении API (например, переименование полей) достаточно обновить логику только внутри WeatherAPIAdapter, чтобы пайплайн продолжал работать.

 - Команда разработки может быстро получить уведомление об ошибке и обновить адаптер, не останавливая работу всей системы. Меньше бегать к серваку :-)

#### Локальный запуск:

Создайте и активируйте виртуальное окружение, установите зависимости, создайте файл .env с переменными окружения, выполните миграции.

Запустите Redis, запустите Django Server, Celery Worker и Celery Beat (если нужен периодический запуск задач) в отдельных терминалах.

API будет доступен по адресу http://127.0.0.1:8000/api/

Документация будет доступна по адресу http://127.0.0.1:8000/swagger/
```
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
celery -A weather_api_project worker --loglevel=info
celery -A weather_api_project beat --loglevel=info
python manage.py runserver
```
